# PC-98 Bootstrap Environment: M6 i386 JIT

Status: **M6 COMPLETE — REVIEWED AND COMMITTED 2026-08-07**

Recorded on 2026-08-07 for M6 of
`PC98BE-NOCT-IMPLEMENTATION-PLAN.md`. This milestone enables Noct's x86 JIT
in the 32-bit PC-98 Bootstrap Environment, constrains its code arena, proves
interpreter/JIT parity, and verifies execution on an emulated i386 with 6 MiB
of RAM.

The approved Noct snapshot is byte-for-byte unchanged. Its existing PC98BE

host test alone makes its static test arena executable with the i386
`mprotect` system call so the identical generated bytes can run under NX.

## 2. Runtime policy and memory ownership

`NOCT_ENABLE_JIT` now defaults to one. `NOCT_JIT_CODE_MAX` remains a build
variable and is set to **196,608 bytes (192 KiB)** for the product. The
embedded BE command enables JIT and uses threshold one, which compiles a
function on its first call. A threshold of zero means eager registration in
the present Noct runtime; the explicit value one was selected so every
executed function is compiled immediately while unused functions need no
code.

`boot98_noct_options` carries the JIT enable/threshold policy, allowing the
same linked binary to run the interpreter for parity testing. A generic,
non-allocating heap observer records the 192 KiB allocation and its matching
free. Immediately before `noct_destroy_vm`, an optional test callback copies
the generated region; destruction must then free that exact allocation before
the arena reset. Product code does not install the copy callback.

## 3. Interpreter/JIT corpus and lifecycle verification

`boot98-noct-m6-script.h` is the single source of the host and QEMU corpus.
It exercises calls, integer multiplication/addition/modulo, arrays, dictionary
loads, iteration, comparisons, conditional branches, Boolean operations,
bitwise operations, shifts, Float division, Double division, string
conversion, and the Native `Console.write` call. Its exact output is:

```text
JIT:24:14:11:0.3831776:0.383177570093458
```

The host test first executes the corpus through the interpreter, then executes
the same source through forced JIT 100 times and compares the byte-for-byte
console result on every iteration. Each JIT cycle verifies the 192 KiB
allocation, generated-code capture, VM destruction, matching free, zero
current heap use after reset, heap integrity, and zero allocator errors. The
existing deliberate syntax and runtime error return paths remain covered.

Primary command:

```sh
./build.sh noct verify
```

Result: **PASS**.

## 4. Static instruction audit and historical generated-code evidence

The normal object and final-ELF audits reject x87, MMX, SSE/AVX, CMOV,
CMPXCHG, XADD, CPUID, RDTSC, and other post-i386 patterns. During the original
M6 review, the zero-initialized JIT region was also captured before release and
disassembled as raw i386 code. The historical evidence was:

```text
build/logs/boot98-m6-jit-code.bin              196608 bytes
build/logs/boot98-m6-jit-code.disassembly
build/logs/boot98-m6-jit-rejected.txt          empty
```

Result at the M6 review boundary: **PASS**.

The generated-code disassembly gate was retired in M11. Noct's i386 JIT emits
only the basic i386 instruction set, while its code stream may place constant
data behind an unconditional jump. A linear raw-binary disassembler can begin
an instruction inside that skipped data and report a false x87 opcode. The
maintained checks are therefore the static Noct/final-BOOT.SYS opcode audit,
forced JIT execution on QEMU `-cpu 386`, interpreter/JIT parity, and repeated
JIT-region release. The host lifecycle test may still retain a raw capture for
size and lifetime observation; it is not interpreted as a standalone code
image.

## 5. Six MiB i386 QEMU verification

`tests/BOOT-M6-QEMU.CFG` runs the JIT corpus three times. A disposable image
was produced from the canonical i386SX IDE image by the normal image builder
and booted with only the in-tree QEMU:

```text
qemu-pc98/build/qemu-system-i386
  -M pc9801 -cpu 386 -m 6 -accel tcg
  -L qemu-pc98/pc-bios -nic none
  -drive if=ide,bus=0,unit=0,format=raw,
         file=build/tests/noct-m6-qemu.raw,snapshot=on
  -display none -serial none -no-reboot
```

Observed terminal result:

```text
PC98BE M6 QEMU i386 JIT test
JIT:24:14:11:0.3831776:0.383177570093458
JIT:24:14:11:0.3831776:0.383177570093458
JIT:24:14:11:0.3831776:0.383177570093458
Noct M6 JIT PASS: runs=3 peak=2644287 bytes
PC98BE-M6-QEMU-PASS
```

The script returned to the BE command stream before `halt`. The run used TCG,
not KVM, and QEMU was stopped through its own monitor without signalling any
other process. Result: **PASS**.
