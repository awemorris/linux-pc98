# Linux/PC-98 v0.11.0

This release fixes Linux root-device discovery on native PC-98 disks and
improves the zedBSD-to-Linux handoff. The Debian 13/i486 images again resolve
`PARTLABEL=DEBIAN13`, mount the ext4 root filesystem, and enter userspace from
the production graphical menu.

## Highlights

- The Linux NEC98 partition parser recognizes the `IPL1` metadata at offset 4
  of LBA 0 and gives a valid NEC98 table at LBA 1 priority, even when an older
  or unified image also carries the PC/AT `55 AA` signature.
- Native PC-98 images deliberately omit `55 AA`. An unmarked disk that does
  carry `55 AA` is left to Linux's normal MS-DOS/MBR parser.
- NEC98 table validation now checks CHS fields, disk capacity, IPL placement,
  and partition overlap before exposing partitions and their `PARTLABEL`s.
- zedBSD's `/bin/linux` path displays text-only kernel loading progress with
  code/data totals, then clears graphics and text state before entering Linux.
- The BeUI cleanup and Linux handoff paths no longer leave graphics or text
  VRAM debris visible while the kernel initializes.
- The release builder verifies both the `IPL1` marker and the absence of the
  PC/AT signature on every native Debian image before replacing a canonical
  artifact.

## Choosing a disk image

| Image | CPU and userland | Interface and geometry | Minimum RAM |
| --- | --- | --- | ---: |
| `linux-pc98-i386sx-busybox-ide.img.xz` | i386SX, static BusyBox | IDE, H=8/S=17 | 5 MiB |
| `linux-pc98-i386sx-busybox-scsi55.img.xz` | i386SX, static BusyBox | PC-9801-55 compatible SCSI, H=8/S=17 | 5 MiB |
| `linux-pc98-i386sx-busybox-scsi92.img.xz` | i386SX, static BusyBox | PC-9801-92 SCSI, H=8/S=32 | 5 MiB |
| `linux-pc98-i486dx-debian13-ide.img.xz` | i486DX or newer, Debian 13/i486 | IDE, H=8/S=17 | 64 MiB |
| `linux-pc98-i486dx-debian13-scsi55.img.xz` | i486DX or newer, Debian 13/i486 | PC-9801-55 compatible SCSI, H=8/S=17 | 64 MiB |
| `linux-pc98-i486dx-debian13-scsi92.img.xz` | i486DX or newer, Debian 13/i486 | PC-9801-92 SCSI, H=8/S=32 | 64 MiB |

Write the appropriate decompressed image byte-for-byte to a CF card, SD
adapter, SCSI2SD, BlueSCSI, or another block device. Writing an image destroys
the existing contents of that device.

### Rufus

These native images intentionally have no `55 AA` boot marker. In Rufus 3.13
or newer, press **Alt+M** once to enable **Ignore Boot Marker**, then select the
decompressed `.img` and write it in DD mode. Rufus preserves this setting.

## Boot behavior

BusyBox images load `VMLINUX` directly from the FAT16 BOOT partition through
bootsimple. Debian images boot zedBSD first and offer Linux, Remacs, Holoris,
and a shell in the graphical menu.

The Debian Linux action is:

```text
/bin/linux /vmlinux root=PARTLABEL=DEBIAN13 rootfstype=ext4 rw rootwait
```

The Debian IDE image was tested through the production graphical menu to the
Linux handoff, NEC98 partition discovery, ext4 root mount, and Debian userspace
startup. A two-disk test also verified that an `IPL1 + 55 AA` secondary disk is
parsed as NEC98 and can supply the labeled root filesystem.

## Other artifacts

- `vmlinux-i386` is the low-memory Linux 7.1 kernel for i386SX systems.
- `vmlinux-i486-debian` is the Linux 7.1/i486DX Debian kernel.
- `bootsimple.zip` contains the IDE/SCSI55/SCSI92 direct loaders, source,
  installer, verifier, tests, and exact release command lines.
- `bootloader.zip` contains the zedBSD PC-98 loader distribution and DOS tools.
- `qemu-pc98-win64.zip` contains Windows qemu-pc98 binaries, compatibility
  BIOS, required DLLs, and the VirtPC98 frontend.
- `SHA256SUMS` authenticates every uploaded binary artifact.

## Reproducible build

The complete release artifact set is generated with:

```sh
./build.sh release --version v0.11.0
```

The release uses zedBSD commit `3124f26`, Noct commit `487ddfc`, qemu-pc98
commit `46f7016`, and debian-i486 commit `a1e431e`.
